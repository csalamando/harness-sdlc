Paso 1: Problem Statement

La aplicación necesita una nube destino definitiva antes de construir infraestructura: sin esa decisión no hay red, identidad de despliegue, pipelines ni estimación de costos operativos. Existen dos propuestas documentadas con alcance equivalente y costos comparables, y posponer la elección bloquea toda la Fase 6. (Nota: la excepción de base de datos aprobada en ADR-004 aplica a ambas nubes por igual.)

Paso 2: Last Responsible Moment

  • Fecha límite: 2026-08-08
  • Razón: IaC, pipelines y GATE 3 se construyen sobre la nube elegida; cada semana de retraso retrasa el primer despliegue
  • Costo de reversa: Alto
  • Restricciones:
  • Presupuesto: ~USD 450/mes (techo FinOps)
  • Headcount: 1
  • Regulatorias: lineamientos corporativos de nube y red
  • Dependencias externas: custodios de WAF/APIM corporativos; onboarding formal pendiente (ADR-2026-102/103 de la propuesta)

Paso 4: Opciones Consideradas

Opción A: Azure (AZURE.txt v1.0)

  • Descripción: Static Web Apps + WAF corporativo compartido + APIM Premium corporativo reutilizado + Functions Flex Consumption + PostgreSQL Flexible Server (primary + réplica) + PgBouncer integrado + Key Vault + Monitor/App Insights. Identidad validada nativamente en APIM. USD 357,35/mes con reserva FinOps.
  • Paved Road: Sí (ADOPT en tech-radar del proyecto)
  • Tecnologías: Azure SWA, Functions FC1, PostgreSQL Flexible, Key Vault, APIM/WAF corporativos
  • Esfuerzo estimado: 4 semanas
  • Riesgos: onboarding formal al WAF/APIM pendiente; arranque en frío de Flex Consumption; inconsistencia menor en AZURE.txt §3 (APIM Consumption vs Premium — aclarar con el autor)

Opción B: AWS serverless (AWS.txt v2.2)

  • Descripción: Amplify + CloudFront/WAF + API Gateway + Lambda + Aurora Serverless v2 + RDS Proxy + Secrets Manager/KMS + CloudWatch/GuardDuty. Authorizer PoP/SHR propio (Lambda REQUEST). USD 445,06/mes con reserva FinOps.
  • Paved Road: No (HOLD en tech-radar del proyecto como nube destino de este dominio; se mantiene como referencia histórica documentada)
  • Tecnologías: AWS Lambda, Aurora, API Gateway
  • Esfuerzo estimado: 5 semanas
  • Riesgos: authorizer de seguridad propio a mantener; ingesta EA requiere VPN/Direct Connect y egress cross-cloud; RDS Proxy con mínimo facturable que puede superar el ahorro serverless

Detalle del Consejo

Solution Architect — 2026-08-06

La vista de arquitectura marca Azure preferente porque la fuente EA (SQL Server) y la identidad corporativa ya están en esa nube: misma VNet para ingesta y MCP, sin egress cross-cloud.

Respuesta del Arquitecto: Aplicado — fue factor decisivo junto al costo. La dependencia compartida (WAF/APIM) se gestiona como acción derivada de onboarding formal antes del ARB.

Paso 7: Decisión

Decisión Adoptada

Azure como nube destino (Opción A de este documento; "Opción B" en la numeración histórica de la propuesta), aprobada por el dueño el 2026-08-08.

Razones Principales

  • Costo −20 % (USD 357 vs 445/mes presupuesto)
  • Reutilización de WAF/APIM corporativos e identidad validada nativamente en APIM
  • Ingesta EA co-localizada, sin egress cross-cloud; PgBouncer integrado sin costo separado

Consecuencias Positivas Esperadas

  • Infraestructura, pipelines y GATE 3 sobre un solo baseline (AZURE.txt v1.0)
  • Menos código de seguridad propio

Consecuencias Negativas Aceptadas

  • Dependencia de equipos custodios (WAF/APIM) con onboarding formal pendiente
  • Elasticidad de BD por cambio de tier manual (vs. auto-escala de la alternativa)
  • Arranque en frío de Flex Consumption (mitigable con Always Ready)

Qué NO se Decidió

  • AWS serverless: queda como referencia histórica (AWS.txt v2.2 con sus ADRs 2026-001..006)

Paso 8: Re-evaluation Triggers

  • Que el onboarding al WAF/APIM corporativos sea rechazado o imponga costos que eliminen la ventaja
  • Que la verificación con Seguridad concluya que la validación en APIM no equivale a PoP/SHR
  • Fecha de revisión programada: al completar el onboarding ARB o 2027-02-01, lo primero
