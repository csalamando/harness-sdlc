CD — .github/workflows/cd.yml

  • Preflight: detecta si el push toca código desplegable (deploy_needed); workflow_dispatch con environment=dev fuerza despliegue manual (hotfix de infra).
  • Deploy dev: usa credenciales OIDC federadas del environment dev (vars AZURE_*), sin secretos de larga vida. Empaqueta y publica las 3 Function Apps y la SPA.
  • Entornos: dev automático tras CI verde; staging/prd requieren promoción manual y APIM onboarded (EX-01).
  • Rollback: documentado y probado en spec/runbook-deploy-rollback.md (requisito de GATE 3).

Reglas operativas

  • Todo merge a master dispara CI; CI rojo = no hay CD ni GATE 2.
  • Los commits [skip ci] solo se usan para artefactos derivados (dashboard/portal regenerados por el arnés o el bot).
  • Las credenciales de despliegue son OIDC federadas por environment; ningún secreto estático en el repo.
  • Drift del diagrama de pipeline: pipeline_diagram.py check en CI — el diagrama se recrea desde el workflow, nunca se edita a mano.
