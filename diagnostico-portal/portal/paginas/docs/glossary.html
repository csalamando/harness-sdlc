Glosario — Catálogo TI

Versión: 0.1 | Fecha: 2026-08-08

Una sola definición canónica por término. Prohibido usar sinónimos en spec, código o UI.

TérminoDefinición canónica
CatálogoConjunto gobernado de registros de un mismo tipo de entidad (ej.: catálogo de Aplicaciones).
SN (Servicio de Negocio)Servicio de negocio bancario trazable a un macroproceso; su ID es SN-{GUID} y se origina en Enterprise Architect.
ET (Etapa / Subproceso)Subdivisión de un SN; ID ET-{GUID}; se origina en EA.
STI (Servicio TI)Servicio técnico expuesto por una aplicación proveedora y consumido por integraciones; ID STI-{GUID}.
APP (Aplicación)Activo de software con código corto, ciclo de vida CMDB, stack, fabricante, BIA/SOX, RTO/RPO y EOL.
INT (Integración)Flujo de integración entre un origen y uno o más STI/apps destino; tipo (API, batch, mensajería…).
ITSM (Servicio de soporte)Servicio de operación/soporte con SLA objetivo y relaciones a elementos de configuración (CI).
MaestroCatálogo de referencia: Macroprocesos (MP), Grupos de Responsabilidad (GRP), Bases de Datos (BD), Proveedores (PR), Regulaciones (REG), Productos (PRD) y Familias.
Macroproceso (MP)Proceso de la cadena de valor bancaria (Estratégico/Misional/Apoyo) al que pertenecen los SN.
Grupo de Responsabilidad (GRP)Chapter, célula, VP, gerencia, comité o área usuaria con correo de distribución; actúa como responsable u owner de registros.
Tabla puenteTabla N:N que materializa relaciones: relaciones (SN↔STI) y bdAppRel (APP↔BD).
Trazabilidad E2ECadena Macroproceso → SN → Etapa · STI → INT → APP → BD con ITSM transversal (BR-004).
Análisis de impactoConsulta inversa: dado un componente, lista transitivamente todo lo que depende de él ("¿Qué se cae si...?").
Llave rotaFK que apunta a un código inexistente (BR-005).
Regla DQRegla de calidad declarativa por catálogo/campo con condición y criticidad (BR-006, BR-013).
PendienteRegistro con campos críticos vacíos según el diccionario de datos (BR-003).
Revisión periódicaRevisión obligatoria de un registro según su criticidad (Alto=3m, Medio=6m, Bajo=12m).
Maker-checkerFlujo en que el cambio de un Editor solo se aplica tras aprobación de un Aprobador distinto (BR-011).
Soft-deleteBaja lógica (activo=false) que conserva historial y auditoría.
Hard-deleteEliminación física irreversible con limpieza auditada de FKs; exige doble confirmación y rol Admin.
Audit logBitácora consolidada de eventos create/update/approve/reject/soft-delete/hard-delete/import (BR-010).
Hash de integridadHuella calculada por versión de registro para evidenciar su contenido (BR-012).
Reuso de STIScore = # apps consumidoras + # SN relacionados + criticidad (INT suman como evidencia adicional); huérfano = sin consumidoras, sin SN y sin INT (BR-009 v2).
EOLFin de soporte del fabricante de una APP; alimenta el EOL Roadmap.
BIA / RTO / RPO / DRPAnálisis de impacto de negocio; tiempos objetivo de recuperación y punto de recuperación; plan de continuidad. Obligatorios si BIA=SI.
SOXMarca de aplicación sujeta a controles Sarbanes-Oxley.
Clasificación de datosNivel de sensibilidad: Público / Interno / Confidencial / Restringido (BR-015).
EA (Enterprise Architect)Herramienta de arquitectura empresarial (SQL Server) origen de MP/SN/ET; su GUID es la llave de conciliación.
GUID de EAIdentificador único asignado por EA; llave de SN/ET/STI y base de la ingesta idempotente.
WatermarkMarca de tiempo de la última ingesta delta desde EA (ADR-002 PoC).
MCPServicio de consultas controladas sobre vistas autorizadas del catálogo, con credencial técnica read-only (BR-015).
PoP/SHRMecanismo de autorización validado por el autorizador de API (AWS.txt §3.1).
Lector / Editor / Aprobador / AdminLos 4 roles RBAC del sistema (BR-007). Sinónimos prohibidos: "viewer", "usuario", "superadmin".
RDS ProxyPool administrado de conexiones frente a Aurora (si se elige AWS); endpoints read/write y read-only.
ACUUnidad de capacidad de Aurora Serverless v2 (rango propuesto 1-4 por instancia).
FinOps reservaColchón presupuestal del 25 % sobre el consumo técnico estimado.
