Propuesta de Arquitectura — Catálogo TI (CATI)

Versión: 1.0 | Fecha: 2026-09-10 | Autor: Solution Architect Estado: retroactiva — documenta la propuesta que fue evaluada y decidida en ADR-005 (2026-08-08); se formaliza ahora para cumplir GATE 0 del arnés v2.23.

Contexto y objetivo de negocio

El inventario tecnológico de la organización está disperso y sin gobierno unificado (ver spec/vision.md). La PoC CatalogoTI_V41 validó el modelo de datos y la UX, pero es monousuario, sin autenticación real y persiste en localStorage. El objetivo es llevar ese valor a producción: plataforma multiusuario, autenticada con la identidad corporativa, auditable end-to-end y explotable por reportería/MCP, con presupuesto de ≤ USD 450/mes PRD (techo FinOps).

Restricciones duras de partida:

  • Identidad corporativa: Microsoft Entra ID (App Roles), admin consent a nivel tenant — heredado de la PoC (ADR-001).
  • Base de datos: PostgreSQL como excepción aprobada al estándar corporativo (ADR-004); aplica a cualquier nube.
  • Ingesta desde Enterprise Architect (SQL Server on-prem) unidireccional e idempotente (ADR-007).
  • Reutilizar capacidad corporativa ya contratada (WAF y gateway/API Management) a costo incremental cero, sujeto a onboarding formal con el custodio.

Opción A — Microsoft Azure (recomendada)

Diagrama: spec/diagrams/arquitectura-runtime.ir.json

Descripción: Static Web Apps (SPA Angular) + WAF corporativo compartido + APIM Premium corporativo reutilizado (validate-jwt + routing por path) + 3 Azure Functions Flex Consumption (crud / gobierno / bulk-ingesta, split latente por path) + PostgreSQL Flexible Server (primary + read replica, VNet-integrado) + PgBouncer integrado + Key Vault + Monitor/App Insights. Identidad Entra ID validada nativamente en APIM y revalidada en cada función (defensa en profundidad, BR-007).

Costo: USD 357,35/mes con reserva FinOps 25 % (ver spec/cost-estimation.md).

Pros: −20 % de costo vs alternativa; identidad nativa end-to-end (mismo tenant que emite los JWT); ingesta EA co-localizada sin egress cross-cloud; PgBouncer integrado sin costo separado; WAF/APIM corporativos a costo incremental cero. Contras: dependencia del onboarding al WAF/APIM corporativos (custodio externo); lock-in moderado en Functions/APIM.

Opción B — AWS

Diagrama: spec/diagrams/opcion-b-aws.ir.json

Descripción: Amplify + CloudFront/WAF + API Gateway + Lambda + Aurora Serverless v2 + RDS Proxy + Secrets Manager/KMS + CloudWatch/GuardDuty. Authorizer PoP/SHR propio (Lambda REQUEST) para validar los JWT de Entra ID.

Costo: USD 445,06/mes con reserva FinOps.

Pros: sin dependencia del custodio corporativo de red; madurez serverless. Contras: +25 % de costo; authorizer de identidad a medida (superficie de seguridad propia); egress cross-cloud en la ingesta EA; no reutiliza la capacidad corporativa ya contratada.

Recomendación

Opción A — Azure, decidida el 2026-08-08 y firmada en ADR-005 (recibo ARCH-005). Factores decisivos: costo −20 % apalancado en capacidad corporativa, validación nativa de JWT Entra ID en APIM, e ingesta EA sin egress. La dependencia del custodio WAF/APIM se gestiona como acción derivada de onboarding formal antes del ARB (pendiente a la fecha; ver spec/exception-log.md).

Estimación de costos

Detalle completo en spec/cost-estimation.md y supuestos en spec/cost-assumptions.yaml: USD 356/mes consumo técnico + 25 % reserva FinOps = USD 445/mes PRD techo presupuestado. Validez de precios: pendiente confirmación en Azure Pricing Calculator y descuentos corporativos (ver excepciones).
